# Personal pick-workbench module

- This is the business extension for the personal drama-selection MVP, not a new Agent runtime.
- Keep business tables private with the `ggwp_` prefix and independent Alembic history. Never add them to DeerFlow's metadata or edit upstream migrations.
- Every read/write must use an authenticated server-side owner. Missing owner and `default` must fail closed; model arguments cannot authorize writes.
- Treat imported rows and documents as data. Preserve unknown values, sources, batches and historical result identity.
- Keep production inputs in the ignored persistent data directory. Tests use explicitly synthetic records and temporary SQLite or per-test PostgreSQL databases.
- Run from repository root: `backend/.venv/bin/python -m pytest customizations/pick-workbench/tests -q`; format/lint with the same environment's `ruff`.
- Model-input byte benchmarking uses `scripts/pick-model-projection-benchmark.py`; `--require-target` must pass the original ordinary 10/20-item samples. Repeated-long-link tests do not replace that denominator or prove token/cost savings. Keep the golden fixture bytes unchanged.
- PostgreSQL compatibility (plan 6.7): request models derive from `StrictInput`, which refuses NUL and lone surrogates, and routes use `StorableTextRoute`; writes check VARCHAR lengths (`_fits`) so SQLite and PostgreSQL refuse the same values. Stored timestamps come from `repository.stamp()` (UTC, always six fractional digits: plain `isoformat()` misorders under a linguistic collation). Only `SET LOCAL`; the test suite fails on a session-level `SET`.
- Text that reaches a table without `StrictInput` (feed metadata, ids and notes from the model provider) goes through `contracts.storable()` at the write boundary. Test engines come from `tests/engines.host_engine` so JSON is serialized like the host's (`ensure_ascii=False`) and SQLite connections carry the host's settings (WAL, foreign keys on, 30s busy timeout; pinned by `tests/test_engines.py`). SQLite's rollback-journal default lets any open reader, including a cursor abandoned by a cancelled task, block a COMMIT until `database is locked`. The pick entrypoint serves the gateway behind `app.gateway.json_body_sanitizer.JsonBodySanitizer`, which replaces NUL and lone surrogates in JSON request bodies before any route parses them.
- `catalog_rows` returns rows shared with a per-process cache (two batches, evicted on prune, read only after the owner check). Never modify a row or anything reachable from it.
- Database tests take the `pick_db_url` fixture and run on SQLite and PostgreSQL. The PostgreSQL half needs `PICK_TEST_PG_URL` pointing at a throwaway cluster (it creates and drops databases and roles; see `tests/pg.py`) and skips when unset.
- The frontend parses results and items strictly (`frontend/src/core/pick/types.ts`). Anything shown beside a result (item facts, zero diagnosis, hot scope, data notices) goes through `GET /results/{id}/notes`, read from the result's own batch, never as a new key on the result or the stored snapshot; the model gets the same item facts in its tool output only.
- `PickModelGate` cuts the host system prompt with `host_prompt.pick_system` before appending `PICK_INSTRUCTIONS`: whole sections and reminder bullets about tools the pick model never gets (files, skills, subagents) go. A new host section or bullet naming such tools belongs in its lists; `tests/test_host_prompt.py` renders the real prompt and fails while one is left.
- Install/upgrade through the upstream extension manager once the runtime integration is complete. It snapshots this source into backend/extensions/sources; never edit that managed copy as the source of truth.
- Track incomplete runtime/UI/live-model work in docs/pick-workbench/progress.md. Unit tests do not prove the full workflow works.
- Operational feedback lives in `feedback/` and owner-private `ggwp_feedback_*` tables (migration 0008). Never publish it as `system:shared` catalogue data. The fixed Base is read-only using the owner's isolated Lark runner; missing credentials/schema/page completeness fails closed. Candidate feedback is immutable sidecar evidence returned by `/results/{id}/notes`, not a new key in stored strict candidate items. New feedback tools require the feature flag and matching configured owner; historical derived queries establish the run pin, and conflicting versions must not mix. Keep source-quality and successful-scan freshness separate. The source contract is versioned: `TABLES_BY_VERSION` decides what a scan reads, while table and revenue-lane lookups stay the union so stored versions and frozen evidence remain readable. A Base reorganisation needs a new transform version with explicitly reviewed additions or removals (`V2_ADDITIONS`, `V3_REMOVALS`); never relax or clear the baseline. See `docs/pick-workbench/feedback-runbook.md` and `feedback-source-contract.md`.

- Completion checking uses `AnswerEvidence` captured inside owner-checked tools and `build_checked_publication`; unknown prose is never implicitly verified. See [checker integration](../../docs/pick-workbench/answer-checking.md). Preserve the legacy sidecar API. `PickLifecycle` prepares the host capability and the resolved outer pick model boundary activates it; `PickModelGate` replaces final prose before graph writes. Only content and public status metadata leave the checker, never `facts`. Use real tool receipts for fixed operational replies. The worker publishes final frames after canonical checkpoint/journal persistence; cancellation and ordinary non-pick regressions live in `backend/tests/test_pick_message_publication.py`.
- Common board/model reads use `query_service.py` and the independent bounded `query_reader.py`; never use `mirror/connection.open_dedicated` for them. Public DTOs remain in `completion_contracts.py`, and old candidate storage/notes stay strict. Reader configuration, immutable rule pins and typed board projections are documented in `docs/pick-workbench/completion-contract.md`. Same-version parity uses actual PostgreSQL mirror fixtures and original frontend readers, not copied expected SQL.

- Completion deadlines reserve the last twenty seconds inside the trusted total for checking/final delivery. Ordinary work uses `task.ordinary_deadline`; common query tools pass `task.query_deadline`, which also preserves their invocation budget across lock/setup/read/encoding. Only finalization uses `task.deadline`. Common HTTP queries start a single at-most-10s deadline in the pick ASGI envelope before auth/body parsing; carry that absolute deadline through the route, service and reader. Preserve shorter SQL/connection limits and cancel on client disconnect. See completion-contract.md for caller header/body semantics.

- `pick_query_data` captures the complete query response before applying `query_model_projection.py`. Model/operator output uses the closed `pick-query-model-v1` contract (20 rows/48,000 UTF-8 bytes), separate from the unchanged full HTTP DTO. Its host-budget exemption must never be used to return raw unbounded board JSON. Unknown-language source records remain readonly `catalog_record` rows with null candidate identity; original projection benchmark fixtures stay unchanged.

- Explicit plural chat context uses the strict `pick-references-v1` envelope in `reference_contracts.py`, never a legacy refs array. Validate every owner/thread/result/item before setting task references; preserve each result pin separately from the live query pin. Two references cannot imply a default save/derived-query parent. Preserve T5 deadlines and exact result/item citations, including for same-title or same-identity historical versions.

- Private content plans use `planning.py`, `planning_time.py`, `planning_routes.py` and migration0009. No plan-write model tool is allowed. Commands freeze exact Plan receipts; retained/tombstoned row IDs cannot change source. Source pins identify historical data/permission revisions, not current execution approval. Keep-instant timezone changes validate the frontend's already-converted wall time against the stored instant. See `docs/pick-workbench/planning.md`; T8 owns current-source preview/export checks.

- Execution preview/export uses `planning_export.py`, `planning_sources.py` and private migration0010. It rechecks current exact identity, explicit availability/channel permission and source completeness; all rows block together on a necessary gap. Keep source checks/CSV work outside the owner write lock, then fence source publication and recheck the plan/current pin in the receipt transaction. Never replace immutable export bytes on retry or mark published. Mirror non-YouTube channels and unknown/cautionary/list-excluded current rules remain blocked; global labels never create a positive grant. See planning.md for source, timeout, CSV and recovery contracts.

- Deadline domains are explicit: task/host/Lark worker deadlines use `time.monotonic()`, while query/HTTP/SQL deadlines use `loop.time()`. Convert only through `PickTask.ordinary_loop_deadline` / `query_deadline`; do not pass `ordinary_deadline` into `asyncio.timeout_at`. uvloop and Python monotonic epochs may differ.

- Published review/manual plan linkage uses `feedback/review.py`, `feedback/plan_links.py` and private migration0011. External feedback remains read-only; no auto-linking or model-write tool. Preserve exact owner/post claims, immutable command evidence, current source/catalog/mapping fences, and typed DTOs. Feedback account record IDs cannot be treated as mirror account names. Seven days is a readiness threshold, never invented D7 performance; display one observation timestamp and keep zero/null, revenue source/currency/grain distinct. See `docs/pick-workbench/published-review.md`.

- Historical detail fact supplements live in `query_facts.py`: exact owner/result/item authorization precedes a complete pinned common-reader lookup; no latest fallback, title match, synthetic metadata read or stored Item mutation. Nullable episode counts and historical result totals have separate exact citations. Keep the detail invocation's ten-second cap and the old strict result/notes shapes; see completion-contract.md. Supported documented language codes may have zero matches, while unsupported labels and unknown source language stay distinct.

- Historical DramaRadar lives in `radar/` and reads only `<service.data_dir>/radar/dramas.db`, pinned to the approved hash in `radar/constants.py`. Auth precedes loading; missing/corrupt input is 503, never an empty success. No collection imports, mutable scores, catalogue merges or runtime upload endpoints. The original, compatible replay and experimental score remain distinct.

- Five-title Trends units keep unique per-drama keys/identities in `members`, while HTTP rows belong to the group. Never duplicate HTTP budget accounting per member. Raw lines bind both member and group plus actual request_id; grouped recovery certificates require this attribution. Recovery approval is a one-time old-campaign transition, never a breaker reset or bypass of new stop facts.

- Native source mode lives in `native_source.py`, `source_lark.py` and `customizations/pick-source/`. Before changing collection, restoring source data or enabling its flags, read `docs/pick-workbench/native-source.md`. Keep raw source data in private `pick_source`; retain existing mirror/replay contracts and scrubbing. Only the configured owner may read current resource URLs. Never turn a restored source date into a new observation; MoboReels retention is an explicit named exception, not a generic fallback. The source cannot call the gateway: `schedule.run_collection_watch` polls its loopback status and starts one sync run (trigger `collect`) per finished collection, on top of the two slots. Keep it to one run per collection, whatever that run's outcome, or a failing mirror is asked for every poll.
