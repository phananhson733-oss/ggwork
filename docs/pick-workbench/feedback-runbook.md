# 飞书运营反馈：配置、验证与回滚

功能默认关闭，读取固定「短剧发行管理」Base，不写飞书。业务数据私有，不能沿用共享剧库的 system:shared 权限。

当前生产已按用户明确授权启用反馈与小时调度，首个真实scheduled同步及反馈工具读取已通过；部署默认值仍保持关闭。最新运行证据与限制见[生产启用记录](releases/2026-10-08-feedback-production-activation.md)。

## 配置

| 环境变量 | 默认 | 含义 |
|---|---|---|
| PICK_FEEDBACK_ENABLED | 关闭 | 只有字面值1启用 |
| PICK_FEEDBACK_OWNER_ID | 空 | 被授权使用这份反馈的宿主用户ID；启用时必须有效，不是default/system:shared |
| PICK_FEEDBACK_SCHEDULE_ENABLED | 关闭 | 字面值1启用每小时刷新；使用与手动/查询相同的持久租约 |

owner必须从服务端真实认证用户取得，由部署者配置；模型、客户端不能指定owner/base/table/SQL。源访问使用该用户在能力中心已连接的飞书凭据，通过既有隔离CLI执行器运行。不能用开发者本机token替代该用户的服务器凭据。

生产启用需要完成真实只读验收，并有对应部署/调度授权。安装或部署代码本身不会自动开启上述变量。

## 首次验证

1. 更新并安装业务扩展的托管快照；确认源码与托管副本匹配。
2. 在独立测试环境运行迁移0008，验证旧候选和保存清单不改变；私有反馈表不授予公共API/共享资料读角色。
3. 以真实owner登录，确认飞书授权能够读取16表（原15张业务表加外部ID映射表）的字段和全部分页。浏览器登录不等于服务端有token。
4. 查询 `/api/pick/feedback/status`，触发 `POST /api/pick/feedback/sync`，核对每表完整性、最近读取时间、来源质量。
5. 首次字段绑定核对field_id/type/关联目标；后续按稳定ID读取。v1到v2只允许本次审核的新增字段及映射表，原有字段ID、类型、属性和语义必须保持。首次成功升级后恢复严格基线；其他新增业务字段、删列或类型变化返回schema_changed，核对后再刷新，不清空基线绕过。
6. 对具体帖子、零值、缺失、跨语种同名剧、账号级收入、手动出单各回查真实样本。自动/手动/RS/汇总收入不能叠加。
7. 生成候选，检查notes附有反馈版本；更新来源后旧候选仍保持原依据，新的判断使用新的成功读取。
8. 只有另行启用调度后，才观察下一次实际小时任务。一次手动成功不等于定时已验证。

## 用户侧行为

- 资料导入区有独立“运营反馈”状态面板，与RealShort目录同步分开。
- 新选剧/反馈策略查询先刷新，本轮固定版本。20秒等待覆盖任务获取、数据库等待和来源等待。
- 超时返回refresh_pending及可用的反馈任务凭据；稍后使用同一feedback_refresh_id继续，不重复发起新扫描。凭据只可访问所属用户的任务，完成后的有效恢复窗口为5分钟。调用者超时或断开后停止其状态轮询，已受理的共享抓取任务继续。
- 页面在尚未取得run_id或首次状态仍为空/旧运行时继续观察，最多60秒；届时显示“尚未确认”，不推断任务成功或失败。手动查询可以恢复观察；旧请求迟到的结果不会覆盖新结果。
- 有反馈版本的候选先解释并验证反馈，再将候选和冻结证据一起提交；解析、写入或取消失败不会留下缺少反馈的可见候选。已有历史候选不会因重试而补写新依据。
- 来源/授权失败不把旧数据冒充最新。纯榜单请求仍可返回榜单，明确没有用上反馈。
- “换一批”继承绑定候选反馈版本；本轮若已经固定另一个版本，会明确拒绝混用。旧详情读取冻结证据，不触发最新刷新。
- 当天、超过30天停止刷新、来源partial、混合账号/语言等限制随结果呈现。国家维度、D7/转化率缺数据时不推断。

## 诊断

| 状态/错误 | 处理 |
|---|---|
| disabled | 检查是否有启用授权，默认行为正常 |
| 401/403 | 登录身份或来源owner不符；不通过修改请求owner绕过 |
| auth_required | 在能力中心飞书插件修复当前用户授权，只补实际所需scope |
| schema_changed | 对照上一成功manifest检查字段ID、类型、必需列；不要清空版本后重试来绕过 |
| incomplete | 检查分页、表范围、条数、manifest；失败批次不会发布 |
| source_changed | 来源在读取中变化，已有限重试；稍后再读，不宣称跨表事务快照 |
| capacity | 检查真实记录数与字节量，评估读取策略后再调整界限 |
| lease_expired | 上一执行者未完成；下一合法刷新可接管；旧执行者不能再发布 |
| receipt_expired | 为新的判断重新刷新，不能拿陈旧receipt声称最新 |

应用日志只输出安全错误码/异常类，不输出凭据、财务行或原始上游错误正文。HTTP状态只含安全运行元数据，不含manifest正文及owner标识。

## 历史与回滚

原始反馈版本和被候选引用的证据不自动删除。更正和来源删除进入新版本，不覆盖旧候选。候选反馈存放在 `ggwp_feedback_result_evidence`，通过已有 `/results/{id}/notes` 返回，不修改严格候选/items协议。

回滚时关闭feature与schedule，正常停止服务任务；保留数据库版本与候选证据，旧目录/榜单/确认保存仍可使用。不默认执行破坏性降级或删除反馈表。

## 验证分层

合成源+真实SQL+真实HTTP/浏览器用于验证软件链路；不能替代真实飞书CLI输出、权限和全量分页验收。当前完成证据与剩余项记录在 `feedback-acceptance.md` / `feedback-progress.md`，不得把定向测试通过称为生产已上线。

## 真实来源耗时与运行边界

NDJSON记录读取使用CLI允许的2000条/页，字段读取200列/页；仍逐页校验manifest和重复记录，单artifact上限8MiB不变。完整双扫描需要分钟级后台执行，不能以20秒前台等待作为任务超时。后台作业预算30分钟，持久租约为预算加30秒；超时不发布，旧完整版本保留。前台仍最多等待20秒并返回pending receipt，后续沿同一作业继续；调度和并发请求不另起重复作业。

本机A14验证使用用户明确完成的只读授权，不等于云端owner凭据已配置。不要复制本机token到云端；部署时使用宿主已有的用户授权入口。

## 剧集映射维护

按[映射维护说明](feedback-identity-mapping.md)维护主表身份、外部ID命名空间和收益粒度。运行时只读来源，映射与业务记录一同进入不可变的v2快照；历史v1快照、hash及候选证据继续按原解释读取，HTTP回复协议仍为feedback-v1。新建字段和一次性待确认候选回填不代表生产反馈或定时任务已启用。
