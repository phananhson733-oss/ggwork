# Trends 持久状态与状态密钥（TR-04）

代码：`ggwork_pick/observe/{crypto,state}.py`、`ggwork_pick/observe/trends/cookies.py`。设计 4.3、4.4；计划 TR-04、D17、D18、D23。

## 用在哪里

- **本机阶段 0（TR-05）**：状态存在一个加密的 JSON 文件里，本页主要讲它。
- **金丝雀与生产**：状态存在 0007 的 `ggwp_obs_runtime` 行里（TR-13 的 `DbStateStore`，D17），不用这个文件；cookie 罐以密文存进 Text 列（D18），用的是同一个状态密钥。

状态里有：熔断暂停截止时刻 `paused_until`、限速器、熔断与预算三个状态机各自的数据（TR-03）、cookie 罐与绑定的 UA。设计 4.3 的规则是**状态读不到，当天就不跑**：崩溃重启后换新 cookie、按全速重来，正是脚本包被放大限流的原因。所以文件不存在、解不开、权限不对，一律拒跑，从不自动新建一份空状态。

## 状态密钥

两个变量**只设一个**，都设或都不设都以退出码 2 拒跑（此时还没读状态，更没有发任何请求）：

| 变量 | 内容 |
|---|---|
| `PICK_OBS_STATE_KEY` | 一个或多个 Fernet 密钥，逗号分隔；第一个用来加密，每一个都能解密 |
| `PICK_OBS_STATE_KEY_FILE` | 密钥文件的路径。文件须属于当前用户、权限 600 或更窄、不是符号链接；内容同上，逗号、空格或换行分隔 |

本机生成密钥，直接写进 600 的文件，不在终端上显示：

```sh
mkdir -p ~/.config/ggwork-obs && chmod 700 ~/.config/ggwork-obs
(umask 077 && backend/.venv/bin/python -c 'from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())' > ~/.config/ggwork-obs/state.key)
export PICK_OBS_STATE_KEY_FILE=~/.config/ggwork-obs/state.key
```

（在仓库根目录执行。）密钥和状态文件分开放，备份时也不要放在一起。Railway 上只给 `pick-obs-trends` 服务配 `PICK_OBS_STATE_KEY`（计划第 10 节 S5），值由用户填。

**轮换**：新密钥放在最前面，`PICK_OBS_STATE_KEY=新,旧`。下一次运行读状态时，日志出现 `sealed with key #2 of 2`，说明文件还是旧密钥加密的；这次运行一保存，就改用新密钥。确认之后去掉旧密钥。数据库里的 cookie 罐同理（TR-13）。

## 状态文件

- 默认路径 `~/.ggwork-obs/trends-state.json`。所在目录须属于当前用户、权限 700（`--init-state` 新建时就是 700）；文件 600。目录或文件是符号链接也拒绝。
- **首次运行**带 `--init-state`：新建目录与文件，写入空状态。文件已存在时带它会被拒（退出码 2），不会覆盖；之后每次运行都不带。
- 每次保存都是原子替换：先写同目录的临时文件并落盘，再改名覆盖。进程在写到一半时被杀，旧文件完好；它留下的 `.trends-state.json.*.tmp` 在下一次成功保存时清掉。
- 同一个状态文件同一时刻只能有一个进程在用。两个进程先后读了同一份状态，后保存的那个发现文件已被改过，以退出码 3 停下，不会覆盖前一个进程写下的暂停。

## 拒跑时怎么办

| 退出码 | 情形 | 处理 |
|---|---|---|
| 2 | 没设密钥；两个变量都设了；密钥格式不对；密钥文件权限宽于 600 或是符号链接 | 按上一节改好变量或文件 |
| 2 | 带了 `--init-state`，但状态文件已存在 | 去掉 `--init-state` 再运行 |
| 3 | 状态文件不存在 | 首次运行才带 `--init-state`；不是首次，说明文件被删了，见下一条 |
| 3 | 文件或目录权限过宽、不属于当前用户、是符号链接 | `chmod 600` 文件、`chmod 700` 目录后重跑 |
| 3 | 解不开（密钥不对或文件损坏）、内容不合格式 | 先核对密钥是不是换过。确认无法恢复时，状态就丢了，见下一条 |
| 3 | 文件在本进程读取之后被改过 | 有另一个进程在用同一个文件；等它结束，只留一个 |

**不要用删文件来“修好”拒跑。** 删掉再 `--init-state`，等于清零熔断暂停、当日计数和 cookie 罐，正是设计 4.3 要防的。真的丢了状态（密钥丢失、文件损坏）时：当天不再跑，至少等到下一个目标日（02:00 UTC 截止的那天，D23），把原因记进阶段 0 报告，再删掉文件、带 `--init-state` 重建。

## cookie 罐与 UA

- 罐与 UA 绑在一起：罐带着自己的 UA 创建，之后不改；请求头里的 `User-Agent` 与 `Cookie` 总是从同一个罐一起取。换 UA 就是换一个新的空罐。
- 每个目标日最多预热一次：同一场会话跨过午夜仍算一天（D23）。被限流时保留原罐（Google 会先拒新会话）。
- cookie 的值不进日志、报错和 repr，只以密文存放（加密的状态文件，或数据库 Text 列里的 Fernet 密文）。
