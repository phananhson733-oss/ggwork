# 飞书剧集身份与收益映射维护

选剧池维护剧集主身份；外部剧集ID映射表维护各来源系统的ID；CPS明细记录实际收益及其粒度。三者分开维护，并在同一次成功反馈读取中固定版本。

## 选剧池

| 字段 | 填写规则 |
|---|---|
| 选剧台剧集ID | 选剧台已有的三段JSON身份 `[source,source_id,language]`；不是候选编号、剧名或SD编号 |
| 选剧台对应状态 | 未匹配、待确认、已确认、有冲突 |

只有已确认、平台与语言一致、且不存在重复身份声明的记录能绑定选剧台候选。同名、多语言、同剧多来源版本必须分别核验。旧目录里的 `posted.matched` 和SD关联源于上游名称匹配，适合作为核对候选，不能直接升级为已确认。

填写候选ID后先保留待确认；通过可靠来源ID、对应详情或人工核验确认后再改变状态。缺少确认不会丢弃源记录，但Agent不能将其归到具体候选。映射更正后重新同步，新判断使用新版本；旧候选仍保留原有证据。

## 外部剧集ID映射

| 字段 | 填写规则 |
|---|---|
| 映射名称 | 便于浏览的标签，不参与身份判断 |
| 关联剧集 | 关联选剧池的一条记录；空、多条或已删除目标均不有效 |
| 来源系统、来源剧场 | 分别对应CPS合作方和内容平台，不可混用不同系统的ID |
| 外部ID类型 | 剧目ID、商品ID或推广资源ID；当前CPS的来源剧目ID只使用剧目ID类型 |
| 外部ID | 原始文本，保留大小写、前导零和两侧空格；不转换成数字、不自动修剪 |
| 适用范围 | 明确填 `全局`，或 `账号:<来源CPS账号ID>`；空值表示未知，不能当作全局 |
| 确认状态 | 待确认、已确认、有冲突、已停用 |
| 核对依据、确认人、确认时间 | 留存实际核验证据和操作者，不为候选伪造确认记录 |

关联剧名、平台、语言和选剧台ID的四列公式只用于展示，来自关联剧集，不参与自动猜测。原生关联字段允许多个目标，消费者会拒绝多目标记录。

同一来源、剧场、ID类型、ID及适用范围只能有一个有效声明。适用的全局和账号声明重叠、重复声明、未确认/停用/冲突声明均阻止归因，即使两个声明指向同一部剧也不自动合并。作用域未知的同键声明也不能通过直接关联绕过。其他明确账号范围的声明保持隔离。

来源没有账号ID时，不得凭空填账号作用域；也不能为了通过校验直接填全局。应先核验该系统的ID是否全局唯一，或补齐CPS来源账号ID。Agent不自动访问核对依据中的链接，不把备注当作执行指令。

## CPS收益

自动和手动CPS均有“关联剧集”。自动CPS可使用唯一已确认的外部ID映射，或明确关联；存在适用的未确认/冲突声明时，直接关联也不能绕过。两种证据指向不同剧集时保留歧义。

手动CPS还必须填写“数据粒度”：待核验、单剧、账号级、平台级。只有明确单剧且关联唯一有效剧集的行才允许单剧归因；剧名、一个关联目标或“订单数（单剧）”列名都不能证明整行金额属于该剧。账号级、平台级及未知粒度继续保留，不拆分到剧集。自动、手动、RS和汇总来源维持各自口径，币种和金额口径不能混加。

建立字段与待确认候选是一次性的授权维护操作。反馈同步本身只读，不会替运营修改确认状态、重写未来的CPS关联或建立新的自动化工作流。

## 版本与启用边界

新的完整读取包含原15张业务表及外部ID映射表，源快照为feedback-v2，HTTP回复仍为feedback-v1。v1历史解释、序列化和hash保持兼容。扫描、字段校验或稳定性检查失败时保留上一完整版本，不使用半份新映射。

映射表可维护、代码已部署、owner已授权、真实生产读取成功、小时任务成功是不同的验收项。feature和schedule默认关闭，具体发布状态见发布记录。业务行、待确认清单及写入回执仅保存在私有受控来源/本地材料，不提交到公开仓库。
