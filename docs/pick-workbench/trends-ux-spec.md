# Google Trends 标签与重点信息 UX SPEC

2026-10-08 · 设计要求；前端实现、30 项相关测试及本地视觉验收已完成，生产发布记录另行登记。

适用于选剧资料的综合列表、历史趋势信号、Google Trends 日级采集记录及对应详情。目标是让用户扫描列表时，直接辨认趋势信号、关键数值与证据限制。保持 GGWork 的布局、字体、留白和品牌风格，同时保留业务所需的语义色。

## 1. 设计原则

**信息语义优先于整体低饱和风格。主题统一不得把趋势标签、风险提示和重点指标全部降为灰色，也不得统一染成品牌青绿色。** 业务语义色是设计系统的一部分，不受主 CTA 数量限制；渐变仍仅用于主题规定的主 CTA。

颜色用于说明已存在的状态，不改变判定阈值、评分、排序或采集行为。绿色不表示推荐购买或保证热度；历史标签必须保留“历史”，不能借强调色变成当前实时结论。增长百分比不直接决定规则标签，例如“未命中增强信号”与正增长可以同时出现。

## 2. 标签颜色映射

复用 `frontend/src/styles/ggwork-theme.css` 的语义 token。使用浅色底、深色字、适度边框及文字或图标形成可辨识标签；不要用整行高饱和底色制造重点。

| 标签或状态 | 语义色 | 视觉重点与解释 |
| --- | --- | --- |
| 历史末段突增 | success 绿 | 上升图标、半粗文字；强调历史窗口末段信号，不使用报警红 |
| 历史增速上扬 | success 绿 | 上升图标、半粗文字；保留完整标签以区别突增 |
| 历史持续爬升 | success 绿 | 上升图标、半粗文字；与普通题材标签明显区分 |
| 历史高位平稳 | info 蓝 | 平稳图标、半粗文字；表达值得关注的历史高位，不暗示正在上涨 |
| 未命中增强信号 | neutral 中性 | 清晰的中性色边框、深色文字；保留观察，不能呈现为禁用，也不能用红色暗示不值得选 |
| 历史曲线有值／历史曲线有数值 | info 蓝 | 信息标签；有值不等于强信号 |
| 历史曲线全零 | neutral 中性 | 明示“全零”；邻近保留“不代表没有搜索需求”，不使用失败红 |
| 证据不足／没有可用曲线／缺少曲线，疑似默认兜底 | warning 琥珀 | 提醒补证据；不可与有效零值混为一类 |
| 曲线待核验／曲线异常 | warning 琥珀 | 明示待核验，相关指标不用于判断 |
| 较早历史窗口／数据陈旧 | warning 琥珀 | 时钟图标与实际截止日期同时可见；沿用现有时效判断，不新增天数阈值 |
| 已确认采集失败／授权失效 | danger 红 | 仅表示明确的运行故障，配失败原因或处理入口；不能根据历史曲线缺失推断采集失败 |

普通平台、题材和来源标签继续使用低强调中性色。状态标签与趋势信号分开表达：一条记录可以同时显示绿色历史信号和琥珀色历史窗口提示，时效提示不得折叠到悬浮提示里。

## 3. 关键指标与阅读顺序

每行按“剧名 → 信号标签 → 关键数值与曲线 → 证据限制 → 核对操作”的层次组织。保持现有表格列与业务流程，不为颜色调整重做页面。

- **变化幅度**：正值用 success 字色并保留 `+` 或上升箭头；负值用 danger 字色并保留 `−` 或下降箭头，旁边说明它是下降幅度而非系统故障；零值为中性色。数值半粗，比较窗口紧邻显示，不能只有彩色百分比。
- **未知和零基数**：未知显示“—”及原因，不着涨跌色；“从零基数出现”使用 info 色与原文，不生成百分比、无穷大或虚假增长率。全零窗口不变成下降或失败。
- **曲线信息**：末日指数、非零日点数量（如 `7/7`）使用清晰深色字和适度字重；日期及“两段窗口比较”说明保持可读。Google Trends 是相对指数，不能呈现为搜索人数或销量。
- **曲线颜色**：可以保留现有图表色，不凭曲线最后一段方向套用信号标签。若按状态着色，必须使用同一语义映射并提供文字说明。
- **数据时效**：本行曲线截止日与“较早历史窗口”在首屏可见；页面最新曲线日期不能掩盖每行不同的日期。
- **实验评分**：分数与等级可半粗，保留“规则参考”；不能仅因 A 级就用成功绿表达已验证推荐，也不能让实验评分压过证据限制。
- **汇总卡**：“带历史曲线”可用 info 强调数量，“无可用曲线／待核验”可用 warning 强调数量及说明；无需整卡染色，不把覆盖数量渲染为业务成功率。

## 4. 主题与可访问性约束

颜色应由语义 token 成对提供前景和背景：`--success-ink/surface`、`--info-ink/surface`、`--warning-ink/surface`、`--danger-ink/surface`；中性标签使用 `--ink-2`、`--raised`、`--line-strong`。组件内不另建硬编码色板，也不让全局品牌样式覆盖这些语义。

明暗模式及 evergreen、tide、Aurora 主题保持相同状态含义。普通文字对比度验收目标至少 4.5:1；表达状态所必需的图形对比度目标至少 3:1。若现有 token 在特定组合不达标，应修正该组合，不能通过取消语义色或减淡文字规避。

每个状态必须有可读文字；颜色和图标只提供冗余提示。装饰性图标对辅助技术隐藏，不重复播报标签。手机端允许标签换行，不能截掉“历史”“未命中”“待核验”等关键限定词；hover、选中、键盘 focus 状态不得覆盖标签语义或降低可读性。

## 5. 验收样例

以下数值来自需求截图，仅作视觉样例，不作为生产数据或规则阈值。

| 样例 | 应呈现的效果 |
| --- | --- |
| Return of the King：未命中增强信号，+9.2% | 清晰中性信号标签与绿色正增长并存；不因正增长改成“持续爬升” |
| Off the Ice：历史高位平稳，−1% | 蓝色信号标签、带负号的下降数值；历史窗口提示保持可见 |
| Taste of the Wild：历史持续爬升，+1.7% | 绿色信号标签与绿色正增长，显著区别普通灰色题材标签 |
| 有效全零、缺少曲线、曲线异常、已确认采集失败 | 分别呈现中性、琥珀、琥珀、红色及各自文案，不合并为“无热度” |

实施完成需验证：

1. 列表与详情对同一状态使用相同颜色和文案；未知标签安全回退为中性，不臆测积极或失败状态。
2. 上述样例在亮色、暗色、三个品牌主题、桌面及手机下均可识别；灰度视图仍可通过文字和符号辨别状态。
3. 用渲染后的真实前景／背景检查对比度，检查 hover、选中与键盘 focus；提交有代表性的浏览器截图。
4. 针对状态到语义色映射、未知／零基数／正负值补充前端测试；已有指标、筛选、排序、详情与复查链接行为不变。
5. 验收分别记录“规范更新”“前端实现”“浏览器验证”“生产发布”，不得以文档完成宣称页面已上线。

## 6. 实施落点

标签来源以 `customizations/pick-workbench/ggwork_pick/radar/snapshot.py` 和 `frontend/src/core/radar/presentation.ts` 为准，展示层消费现有状态；这次设计不要求修改后端规则。样式优先复用现有主题 token 与标签组件，只为实际出现的状态补充必要映射。
