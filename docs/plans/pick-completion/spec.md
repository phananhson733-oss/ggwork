## 最终产品结构

主要入口：选剧对话、选剧资料、我的选剧、排期草稿、发布复盘。

1. 选剧对话：输入账号/平台/语种/时间范围/数量等需求；可选择明确的选剧策略；显示实际生效条件、候选和证据，支持追问/换批/保存。
2. 选剧资料：承接候选池、全部剧库、历史榜单、发布记录、剧场规则、单剧证据及同步状态。原有较完整表格继续承担查证职责。
3. 我的选剧：把现有保存、备注、移出、来源回看和幂等回执接成完整入口；提供生成排期草稿动作。
4. 排期草稿：持久化可编辑计划行，明确账号、渠道、日期时间、时区、剧目、文案草稿/备注及来源；校验后导出。
5. 发布复盘：复用已有发布记录和私有运营反馈，按账号/平台/语种/剧目/窗口查看。支持从表现记录返回原选剧依据或再次选剧；不足以关联的记录保持未关联。

典型旅程：
“给账号 A 选 5 部英语剧，YouTube 可发，过去30天该账号没发过，优先本周有依据的剧”
→ 显示实际条件与资料时点
→ 候选卡附入选/排除理由
→ 查看一部详情并和另一批结果比较
→ 确认保存3部
→ 分配下周时间、渠道、账号并保存排期草稿
→ 预览和导出
→ 从已有发布数据回看这些剧的表现。

## 1. 先形成一份业务合同

| 主题 | 建议规则 |
|---|---|
| 候选池与全部剧库 | 候选池用于推荐；全部剧库用于查证和解释未入选。查不到候选不能推断全库没有该剧。 |
| 剧目身份 | 保留稳定源记录身份；标题近似用于“疑似同剧”提示。只有已有可靠映射或人工确认后才按同剧组跨源去重，不直接改现有主键。 |
| 归档/发布/排期 | 归档影响运营管理状态；真实发布事实仍保留。过滤分别表达“归档状态”“实际发过”“计划中”“未匹配/未知”。 |
| 未发过 | 明确账号/渠道/时间范围与匹配完整性。无法完整核对时返回“无法确认”，不给确定性未发布结论。 |
| 渠道规则 | 以有来源和版本的禁发/限剧单/慎用/未知等规则过滤。未知和慎用不能静默当成可发。 |
| 时间 | 榜单期次、事实观察时间、来源刷新时间、镜像同步时间分别保留；不能用今天同步时间替代旧证据日期。 |
| 去重与已选 | 精确源身份默认去重；跨源同剧只按可靠关联处理。已选、已排期、已发布是独立事实。 |
| 排序 | 浏览排序、榜单原始名次、策略推荐顺序分别命名；不能把最新证据默认称为最有商业价值。 |
| 历史结果 | 旧候选保留旧条件、数据与规则版本；“按最新数据再查”生成新结果，不覆盖原证据。 |
| 账号与语种 | 账号由真实数据/用户选择确定；不由语言推断国家，不跨账号/来源混算反馈。 |

为每条规则准备固定合成输入与期望结果；三套实现发生冲突时选择最终产品规则，并记录原因。差异本身不自动意味着某套旧实现正确。

## 2. 聊天与资料页查到同一套事实

优先补齐 AI 所需但资料页已具备的查询：全部剧库精确检索、中文名/源ID查找、日榜日期与周起、账号范围的发布核对、规则详情、候选与完整资料的互相定位。

建议沿用现有镜像版本与后端 Gateway，建立统一请求/响应合同：条件、固定数据版本、规则版本、实际期次、排序版本、总数、截断状态、候选、来源及排除原因。

D5=A 已确认：本方案要求聊天与资料页一致的筛选、榜单期次、发布核对等关键查询，按领域迁至现有 Gateway 共用入口，业务代码归属现有选剧扩展。各领域先用同版本数据对照既有排序、分页、权限、版本回放、统计和错误行为，再切换双方调用；过渡期保留必要的旧读取路径，不一次重写全部资料页 SQL。全库查证、历史榜和账号级发布核对都需补齐。字段、版本映射和错误语义继续细化；不新增部署服务或数据源。

用户验收：同账号、同权限、同版本、同范围和条件，聊天结果与资料页结果及统计一致；若候选池与全部剧库范围不同，界面明确显示范围并能跳转解释。

D11=A 已确认：共用查询采用10秒调用方请求预算，HTTP/Gateway及内部连接、SQL、汇总和响应处理使用剩余时间，不逐层重置；跨进程只能缩短服务端预算。已有更短限制及D10普通阶段截止优先；超时/取消需可重试且释放后端资源，不放宽全局鉴权、SQL或池限制。保留分页与批量查询，分领域切换前测量验证；10秒不是已测得的成功时延保证。

## 3. 强化可信推荐和答案交付

- 复用两套旧实现中的数字、总数、时间、来源、规则引用和全库否定结论反例，改造成新结果/事实结构下的核对器。

- 对结构化推荐和最终决策结论，先准备、核对，必要时最多纠错一次，再发布为最终内容；核对仍失败时展示可确认部分和具体缺口。
- D3=A 已确认：最终选剧正文及候选/排期结果中的可核验事实都进入检查；核对不了的内容明确标为未确认，不作为已核对结论交付。实时展示、复制、刷新历史和失败恢复必须遵守同一承诺。
- D4=A 已确认：核对逻辑留在ggwork_pick，宿主增加选剧专用薄发布接口，核对后的宿主消息作为唯一最终答案。实时流、所有历史读取、复制及后续对话统一使用该内容；必须验证重复回调、断线、取消与普通非选剧运行的回归。当前after-model旁注不能充当发布关口；收尾预算按D10执行，原方案至多一次纠错的上限不放宽。
- D10=A 已确认：在生效总时限内预留最后最多20秒做事实核对、允许范围内纠错和最终交付；普通模型/查询调用的期限同时缩短，进入末段不再启动普通查询。总预算<=20秒仅按剩余时间收尾；总时限、模型次数和原方案至多一次纠错上限不放宽。时间或次数不足只交付已确认部分或明确未完成，不发布未核对正文。该数值是已选择的设计预算，不是响应时延保证。

一开始提供少量透明策略即可，例如：有近期榜单依据、目标账号未发、基于已有表现的复测。先硬过滤资格、身份和数据可用性，再按明确规则排序；卡片展示入选原因、关键排除条件和同分排序。暂不引入难以解释的统一“潜力分”。

## 5. 最小完整排期草稿

在现有业务扩展中增加最小计划对象和计划行，复用宿主身份、现有剧目/候选引用和幂等命令方式。

计划行建议包含：源记录身份、确认同剧关联（如有）、来源候选/条目、剧名/剧场/语种、目标渠道、账号、计划本地时间与明确时区、文案草稿/备注、规则与数据版本、校验状态。

核心行为：
- 从已选剧目或明确候选生成草稿，模型可建议时间和文案，由用户编辑确认。
- 校验缺账号、语种/渠道规则冲突、同账号重复、未知授权/素材状态；只标记真正有证据的冲突。
- 保存和导出前重新核对最新下架/渠道限制，并与生成草稿时的证据分开展示；发生变化时要求修订或明确处理，不能把旧草稿自动视为当前仍可执行。
- D8=A 已确认：下架状态、目标渠道资格及所依赖的来源读取完整性是执行表导出的必需检查。读取失败、字段缺失或明确未知时保留草稿并列明缺口，阻止执行表导出；恢复后按同一已确认草稿版本重验。既有资料年龄告警保留展示语义，不能用“没有告警”推断许可，也不把不相关历史指标过期一律当作阻断。
- 处理夏令时重复/不存在时刻和用户时区；排序与导出不因浏览器时区改变而移位。
- 导出固定列、UTF-8 BOM 与公式注入转义，导出前预览。原12列可作为兼容基础，时区和稳定源身份不能丢失；只有确有旧表消费方时才强制旧列完全一致。
- D6=A 已确认：预览与导出绑定用户确认的草稿版本；导出提交前若版本变化，返回明确冲突，要求刷新、核对变化并重新确认。成功导出固定于该次核对版本，不被后续编辑改变。必要证明包含校验中修改、重复点击和下载失败恢复，复用现有版本检查及重试保护。
- “已导出”不代表“已发布”。发布状态来自真实发布记录或明确的人工登记流程，不用下载文件自动改发布状态。

这一步是内容计划，不是定时运行 Agent，也不承诺自动向平台发帖。

## 一期用户验收场景

1. 从聊天和资料页用相同条件选剧，结果一致且规则可解释。
2. 按具体账号排除已发布，归档记录、未匹配记录和不同观察窗口各自正确。
3. 查某日榜/跨年同名周榜，显示实际期次，缺期提示明确。
4. 同名不同剧不自动合并；同一源记录重复出现不重复保存。
5. 错误数字/总数/来源被拦截或明确标注，纠错失败不伪装成功。
6. 选择3部保存个人清单，刷新、重试、改备注、移除均可用且保留来源。
7. 生成下周排期草稿，编辑账号/日期/时区，预览并下载表格；文件字段与页面一致。
8. 候选生成后下架或渠道规则更新，在导出前被发现。
9. 按历史发布记录回看表现，缺失/未更新/不足观察期不被误读。

- 切换计划或离开页面时，未保存修改提供“留在此页 / 放弃未保存修改”；可保存时提供“保存后继续”。不新增持久化浏览器私有草稿，不承诺强制关闭/崩溃后的未保存恢复。

- 时间以计划时区为准；改变时区时明确选择“保持计划当地时间”或“保持实际时刻”，显示变更预览后确认，不静默平移。不存在的当地时间要求换时刻，重复时刻要求选择含UTC偏移的第一次/第二次。涉及金额或日期的表格值不使用难读的无标签缩写。
- DS06：阻断摘要可定位到具体行；必需来源读取失败与明确禁发分别表述。提示中包含本次尝试时点和重新核对动作；普通资料年龄告警继续只是告警，不自动阻断。
- DS07：参考清单下载保留既有合同与字段，按钮和附近说明写明“仅作选剧参考，未完成排期执行核对”。执行表只能在确认版本/必要证据均通过后生成。浏览器下载触发、服务端文件生成、真实发布为三个不同状态。

DS04–DS07将已有工程约束翻译为界面；统一状态表不新增后端成功语义。9分表示规格可实现，异步竞态和可理解性仍需验证。

## Pass 3：用户旅程与恢复（7 → 9 / 10）

| 步骤 | 用户操作 | 预期感受 | 界面支持与恢复 |
|---|---|---|---|
| 1 | 打开选剧对话 | 知道从哪开始 | 简短示例需求；源已可用时直接输入，源未就绪时按权限提供状态说明/同步去处，不让所有人先做导入 |
| 2 | 提出账号、渠道、语种和数量 | 知道系统是否理解 | 展示实际条件和范围；有歧义先明确，缺少资料不猜测 |
| 3 | 等待查询与核对 | 感到任务在推进 | 显示真实阶段；可以取消；不虚构完成比例，不展示稍后将被撤回的确定性正文 |
| 4 | 查看候选和证据 | 能判断为何入选 | 先看身份、资格/缺口、理由；展开详情或新页查证；返回原批次仍能定位 |
| 5 | 比较两批并选3部 | 保持控制、不怕重复 | 两批有名称/查询时间/条件差异，按稳定源身份对照；当前选择及来源清楚 |
| 6 | 保存个人清单 | 确定真正保存成功 | 以真实回执显示新增/已有；可立即跳转清单；失败保留选择并重试原命令 |
| 7 | 生成、编辑排期 | 能调整而不怕丢失 | 账号、渠道、当地时间及时区可见；显式保存；缺字段留草稿；刷新恢复已保存版本 |
| 8 | 核对与导出 | 知道能否执行 | 阻断解释和定位；修复后重新核对；版本变化先比较、确认；下载的是明确版本 |
| 9 | 之后打开发布复盘 | 相信数据范围 | 不把导出当发布；真实记录、来源和观察窗可见；未关联不会消失 |
| 10 | 从表现返回依据再选剧 | 形成可追溯复用 | 沿已确认关联查看原计划/候选；按表现发起新查询，保留旧依据不重写 |

DS08：第一批/第二批是显式用户选定的结果，两批都显示条件、数据时点和可比较性。不同期次或规则的差异属于事实，不用绿色“更优”概括。相同稳定身份的重复条目只选一次；来源证据不同须明确采用哪一份。跨源同名继续标“待核对”，不自动合并。不默认将视觉比较转成跨批次对话引用；后者遵守原计划的后续阶段与owner/thread校验。

DS09：复盘中“未关联”指没有确认计划关系，“未归因”指不能把表现分配给这部剧，两者不合并成一个标签。列出来源支持的指标和单位；缺值用“未提供/未更新”，测得0才显示0。窗口不足显示“已观察3天”，不能冒充完整7天。不同币种、估算/实际/手工来源不混加。来源尚未启用或owner无资格时给原因；不泄露其他用户是否有记录。

人工关联只显示有权限的真实帖子与计划行，双方身份、账号、时间、来源证据及冲突原因可见。候选搜索不改变自动匹配标准。确认是显式动作，不能因为预先勾选或标题相同而成立。修订旧映射后，新查询用新版本，旧候选仍保留原依据。实际产品可理解性尚需任务测试，故不评10分。

## Pass 5：设计系统对齐（7 → 9 / 10）

DS11复用实际主题，不为缺少DESIGN.md复制一套规范。初始使用宿主当前明暗模式；运营长时间读表，以低噪声、中性表面和清晰文字为主。保留用户主题偏好，不能仅因“数据后台”强制暗色。

| 用途 | 复用的token / 组件 | 规格 |
|---|---|---|
| 页面/内容/次级区 | `--bg` / `--surface` / `--raised`，WorkspaceContainer/Body | 主工作区平静，不给每个字段套卡 |
| 标题/正文/帮助 | `--ink-1` / `--ink-2` / `--helper` | 页面标题24px/32px，区标题18px/26px；业务正文、字段、表格值默认16px/24px；ID等非关键辅助信息14px且可放大 |
| 字体 | 已提交的DM Sans、中文字体回退，JetBrains Mono | 不新增远程字体；mono仅用于ID、对齐时间与数值，不装饰标题 |
| 操作与链接 | Button；`--brand`、`--link`、`--brand-soft` | 一处显著主操作；链接下划线/状态不能只依赖悬停；访问过的证据链接有主题内可区分颜色，实测对比度 |
| 状态 | `--success-*` / `--warning-*` / `--danger-*` / `--info-*` | 图标+文字+颜色；品牌色不能代替“可发/禁发/未知”语义 |
| 表格/筛选 | 既有资料表与表单组件 | 列标题/单位、数值对齐、每行标签，排序不改成推荐价值 |
| 编辑/确认 | Label/Input/Select/Textarea/Dialog/Sheet等既有基础组件 | 现有依赖优先，具体可用组件实施时查证；不引入新表格编辑框架 |

| 浏览器交互 | `--ring`、`--link`、`--brand-soft` | 焦点、选择、caret可辨；不隐藏滚动条；遵循系统高对比模式，不为统一外观强制自绘 |

错误/待核对区域用对应语义前景色，避免淡灰字叠彩底。普通文本对比度至少4.5:1，控件边界与焦点至少3:1；这些是验收目标，不是本轮测量结果。既有无关宿主界面不在本轮重做范围；触及的新流程及其复用组件需满足规格。

## Pass 6：响应式与无障碍（4 → 9 / 10）

DS12规定内容驱动布局，并以以下尺寸作为验收采样，不覆盖宿主已有断点实现。保持同一数据合同，避免手机和桌面拥有不同权限或查询语义。

| 场景 | 导航 | 内容与编辑 | 操作 |
|---|---|---|---|
| ≥1280px桌面 | 复用侧栏，当前入口明显 | 对话主区+候选详情；计划表+单行详情；允许缩放而不挤掉必需字段 | 主操作靠近对象/问题摘要；固定条不得遮住最后一行 |
| 768–1279px平板/窄桌面 | 侧栏可收起，但仍有可见菜单入口和当前页名 | 表格局部横滚；详情按需占用更大区域，不强留三列 | 筛选可折叠，始终显示已生效数量/摘要和清除动作 |
| 320–767px手机 | 顶部标题+可访问菜单抽屉；保留五入口 | 多行列表先显示剧名、当地时间/时区、状态；点行进全屏编辑/详情；完整资料表可切到局部横滚 | 主操作可固定底部但预留安全区；当前选中数量可见；错误可直达字段 |

长中英文剧名允许换行；不靠省略号隐藏唯一身份线索。ID长串可断行，单位和日期完整可读。两批比较在手机上以“仅第一批 / 两批共有 / 仅第二批”分组及详情切换表达，仍显示两批版本/条件，不要求左右同时挤在一屏。200%缩放、320px宽不产生整个页面横向滚动；确属二维数据的表格区域可有明确横滚。

DS13可访问操作要求：

- 原生button、checkbox、label、table优先；可见标签持续存在，不把placeholder当标签，不为简单列表强加ARIA grid。
- 每页一个主要内容区和明确h1；表格caption/列标题、排序状态、菜单当前页和tabpanel语义正确。沿用宿主main，避免嵌套main。
- Tab顺序与视觉阅读一致；Space勾选；Enter执行按钮/表单；无拖拽唯一操作、无悬停唯一信息。列表有真实全选范围说明，不能把不可见旧筛选结果继续纳入动作。
- 编辑层打开时焦点进入标题/首个适用字段，关闭返回触发项；有修改按DS05处理；仅真正模态层才限制焦点。键盘不被表格或滚动区困住。
- 保存/查询结果通过简短`role=status`或polite live region播报一次；错误摘要可聚焦并链接字段，字段错误使用aria-describedby/aria-invalid。核对过程不逐token或每轮轮询重复播报。
- 触摸目标至少44×44px；输入、错误、禁用理由不依赖颜色；loading保留可理解文本。遵循prefers-reduced-motion，内容不等待动画才可见。
- 键盘、屏幕阅读器、明暗模式及高对比模式验证纳入DT08。规格评分9，不假称这些检查已运行。

## Pass 7：未决设计登记与开放边界
