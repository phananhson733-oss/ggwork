用户已授权：把已验收本地 DramaRadar 的完整内容和交互替换到现有 Google 趋势 tab，统一 GGWork 主题，并上线。第二张截图是内容基准；不是再改一次单晚批次表。

## 数据与实现

复用已验收本地试用版 `snapshot.py`、纯 `scorer.py`、只读 SQLite 连接和筛选/导出算法，迁入业务扩展 `radar/`。三份评分（原包保存、兼容重算、实验规则 pilot-rules-v1）维持原规则和逐条错误隔离。固定权重35/30/20/15和原阈值/降权，不更改算法。无曲线/异常/不足14日不评分、不补零/不授予C档；全零保留真实零并不推论没有需求。曲线完整日期和31/32日点不裁切。列表仅携带末7点，详情携带完整数组。

原始 SQLite 来自用户包，DB SHA256 `c359719b80840c2fc27e2255631a83780f60c8c62b19dca3dbe48e2de1eb314c`，ZIP SHA256 `d4be09eb351b9bcd90bdac336fdfa84950c9ed57b6d0c287140b7b23143f2183`。原始文件单独传入 Gateway 私有持久卷 `<service.data_dir>/radar/dramas.db`，不入 Git、不放前端public、不在请求参数接受路径。读取前核验固定hash/SQLite完整性/schema/WAL，失败仅该功能503。首次鉴权后在线程池加载并缓存不可变视图，不阻塞异步事件循环。无需迁移生产数据库。

GET `/api/pick/radar/stats|dramas|dramas/{id}|export` 全部使用现有 server principal 验证，无缺省身份。只读全体登录用户共享该获准历史样本，原有个人清单仍私有。响应 no-store，前端验证响应schema。列表参数沿用本地Spec：组合AND、稳定ID末级排序、null最后、信号视图只含三类增强信号、分页不限制可到达全量；导出忽略分页但保留筛选排序、BOM、CSV文本公式防护和空值。
