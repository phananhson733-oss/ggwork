## 已完成的现场诊断

生产只读报告的最新 target_date 为 2026-10-07（UTC），仍以 `canary_terminated` 拒跑，零请求。历史两晚共 173 条请求记录已重新读取并分析，原始时间线保存在私有产物中；入仓仅保留汇总。

| UTC target_date | 请求数 | HTTP 200 | HTTP 429 | 第一次 429 的请求序号 | 首次/二次限流后的等待 |
|---|---:|---:|---:|---:|---|
| 2026-10-01 | 105 | 102 | 3 | 55 | 约 1,800 / 3,600 秒 |
| 2026-10-02 | 68 | 65 | 3 | 25 | 约 1,800 / 3,600 秒 |

- 两个批次都记录 `user` 节奏：桶容量 4、每分钟补 2。按请求开始时间重放该包络，并在第一次限流后按每分钟 1 的更严格包络核对，未发现超发。这个检查仅验证请求包络，不等于 Google 承诺接受该速率。
- 限流出现在 multiline 和 related 接口。explore 中实际记录的 userType 为 `USER_TYPE_SCRAPER`；这证明服务端的会话分类，不单独证明封 IP、cookie 无效或具体限额。
- 首次和第二次 429 后实际执行了约 30、60 分钟的暂停，后续仍出现 429。没有证据支持“遗漏退避导致连续重试”。
- 历史出口地址未测量，响应 Retry-After 也没有持久化，无法据既有记录区分出口、会话、接口限额等原因。不得给这些未知项补值。
- 日级、全球、100 部简化任务尚未在生产 stable 运行。减少相关查询不会自动证明旧限流原因已消失。

结论：当前没有已证实的限速/退避实现故障可直接修复。已确认直连网页接口受到服务端限流，终止保护正常生效；恢复路径仍需验证。

## 数据接口决策

2026-10-07 用户已确认没有 API。本期使用现有匿名网页客户端，不再把官方 API 权限作为等待项。当天查阅的 [Google 官方页面](https://developers.google.com/search/apis/trends) 仍要求申请 alpha 访问，不可把它当作已可调用接口。

官方 API 的缩放与网站 0–100 序列不同。若使用该接口，应先验证输出合同及跨时间窗语义，再接现有表格；不得直接把不同尺度的数混为同一类数据。第三方服务也必须核实实际账号、限额、费用和日级/地区/空值合同后再实施。

当前恢复路径先准备一个单独登记的直连诊断，而不是重启整晚任务：

1. 固定一个非私人对照词、全球 `WW`、`today 1-m`；不查 related。
2. 单次最多预热、explore、multiline 共 3 次 HTTP。任意 429/403、验证码或同意页即停止，不重试，不更换出口或 UA。
3. 只记录状态、阶段、耗时、允许的 Retry-After 值、userType、序列是否存在；cookie/token/私人请求内容不入日志。
4. 必须记录实际运行位置和部署。Gateway、本机或其他出口的结果不能冒充生产 collector 出口通过。
5. 该诊断是显式、有限的停止后调查；先确认其执行边界，不删除或绕写现有 canary 终止状态，不改变 since、mode、预算或 cron。当前尚未派发该诊断。

## 恢复到可用功能的验收顺序

1. 根据接口权限或受控诊断结果形成可验证的改动；每个结论有实际证据，失败保留。
2. 满足既有恢复条件后，按手册建立新的验收起点；旧失败仍可追溯。禁止仅改 since 获得通过。
3. 取得三个真实有效夜晚：通过负载闸门并实际发出请求，无验证码/同意页、无因限流停用。零请求和合成模拟不计入。
4. 通过后部署采集端的简化任务来源，切为 `stable + a_only + D`，100 部、全球、日级；保持既有预算、租约和停止规则。
5. 验证真实计划与同批 raw、来源日期、数据/无数据/未采集/待完成四种结果、缺日断线，以及两段七日均值和标签。首周记录覆盖情况，不以空表 UI 通过代替采集通过。
